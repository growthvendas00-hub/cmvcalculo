# CLAUDE.md — CMV Studio

Guia de arquitetura para agentes. Leia isto ANTES de explorar; evita re-mapear o código.
Sistema de CMV/estoque/caixa para hamburgueria/pizzaria. Node + Express + HTML/CSS/JS puro (sem framework, sem build).

## Como rodar / testar
- **Porta 3001** (a 3000 é de outro projeto na máquina). Subir: `node src/server.js` (ou `INICIAR.bat`). Deploy: Vercel.
- Antes de reiniciar, **mate a porta**: PowerShell `Get-NetTCPConnection -LocalPort 3001 -State Listen | %{ Stop-Process -Id $_.OwningProcess -Force }`.
- Validação rápida: `node --check public/js/app.js` + contagem de chaves `{`/`}` no CSS. Se houver ferramentas de preview (Claude Preview MCP), há um `.claude/launch.json` com a config `cmv-studio` (node src/server.js, porta 3001) — dá para validar DOM/JS via `preview_eval` mesmo sem a senha (o gate só cobre visualmente). NUNCA grave na API real: `data/settings.json` tem a senha do cliente e os `data/*.json` são os dados de produção dele.
- Depois de testar via API, **limpe os dados de teste** (reset dos `data/*.json`) — o usuário usa os mesmos arquivos.
- Avisos de `LF will be replaced by CRLF` no git são normais (Windows). Idioma de todo texto/UI: **português (pt-BR)**.

## Persistência (dois modos automáticos) — `src/core/storage.js`
- **Local**: grava arquivos em `data/*.json`. **Vercel**: grava num **Vercel KV (Redis Upstash)**, tudo numa única chave `cmv:db`.
- Decide por env: se existir `KV_REST_API_URL`+`KV_REST_API_TOKEN` (ou `UPSTASH_REDIS_REST_*`) → KV; senão → arquivos. Exposto como `storage.KV_ATIVO`.
- No modo KV, `server.js` tem middleware em `/api` que **hidrata** (`kvHydrate`) no início da request e **grava** (`kvFlush`) ao responder — ele faz isso embrulhando `res.json` (flush só ocorre se `DB_SUJO`). Por isso: **handlers que gravam devem responder com `res.json`** (não `res.send/sendStatus`), senão o flush não roda. O webhook usa `res.sendStatus` e por isso chama `storage.kvFlush()` manualmente.
- `lerJSON(caminho, padrao)` / `salvarJSON(caminho, dados)` são a API interna; tiram BOM; no modo KV operam sobre `DB[chave]` (chave = nome do arquivo sem `.json`).

### Durabilidade / proteção contra perda de dados (IMPORTANTE)
- **Escrita atômica (local)**: `salvarJSON` grava em `arquivo.tmp` e dá `renameSync` → nunca fica JSON truncado se faltar luz/processo morrer.
- **Anti-wipe (KV)**: `kvFlush` NUNCA grava um DB vazio (`{}`) por cima de dados que existiam (`DB_TINHA_DADOS`). Protege contra um bug zerar tudo.
- **Backups automáticos diários (local)**: `backupDiarioLocal()` cria `data/backups/backup-AAAA-MM-DD.json` no máx. 1×/dia (disparado pela 1ª gravação do dia), rotação 14 dias. `data/backups/` é **gitignored**.
- **Backups automáticos diários (KV)**: `backupDiarioKV()` é chamado ao fim de `kvFlush` (1ª gravação do dia; marcador em memória + `EXISTS` p/ instâncias serverless novas) → grava `cmv:db:bak:AAAA-MM-DD` no próprio Redis, rotação 14 chaves. `listarBackupsKV()` lista; `GET /backup/info` devolve `info.kv.backups` quando KV ativo.
- **Pré-restauração**: antes de restaurar, `backupPreRestauracaoLocal()` (arquivo fixo `backup-antes-de-restaurar.json`) ou `backupKV()` guarda o estado atual → dá pra desfazer uma restauração ruim.
- **Export/Import**: `exportarBanco()`/`importarBanco(dados)` (todas as coleções **menos settings** — nunca exportar senha). `backupKV()` grava foto datada `cmv:db:bak:AAAA-MM-DD`. `infoBackupLocal()` = status.

### Coleções (mesma estrutura nos dois modos)
- `ingredientes` (array) · `fichas` (array) · `custos_fixos` `{meses:[]}` · `fornecedores` (array)
- `movimentos_estoque` (array) · `contagens` `{contagens:[]}` · `caixa` `{lancamentos:[]}`

## Módulos core (`src/core/`)
- **units.js** — `UNIDADES` (kg/g/L/ml/un → base g/ml/un), `UNIDADE_EXIBICAO`, `paraBase`, `exibicao`, `existeUnidade`, `unidadeBase`, `dimensao`. **Embalagem**: `conteudoBaseEmbalagem(emb)`, `converterParaBase(qtd, unidade, base, embalagem)` (aceita unidade `'emb'`). Use SEMPRE `converterParaBase` para converter entrada do usuário → base.
- **cmv.js** — `arredondar`, `calcularCustoBase(valor, qtd, unidadeCompra)`, `calcularCMV(ficha)`, `calcularRateioMes(mes)`, `propagarPreco(ing_id)`, `validarFicha`, `classificarCMV`, `temPreco`, `CATEGORIAS_FIXAS`, `VENDAS_TIPOS`, `totalVendasMes`.
- **estoque.js** — `aplicarMovimento({ingrediente_id,tipo,quantidade,unidade,motivo})` (tipo: entrada/saida/ajuste), `registrarContagem({itens,tipo,observacao})`, `panorama()`, `visaoIngrediente(ing)`, `estoqueAtual/estoqueMinimo`, **`consumoDoDia(YMD)`** ("quanto saiu em R$ no dia": soma saídas + consumo das contagens; ajustes ficam de fora; valora pelo `custo_base` gravado no movimento — todo movimento novo grava o custo da época; antigos caem no custo atual).
- **caixa.js** — `CATEGORIAS` {entrada:[],saida:[]}, `resumoMensal(mes)` (agrupa por dia, fuso SP).
- **historico.js** — `snapshot(YMD)` (reconstrói estoque ao fim do dia), `timeline(ing_id)`, `comparar(a,b)`, `hojeBR()`. Fuso fixo SP (-03:00).
- **auth.js** — senha scrypt+salt; sessão = token HMAC (segredo em settings.auth_secret) em cookie HttpOnly `cmv_sessao`. `configurado/verificarSenha/definirSenha/rotacionarSegredo/criarToken/tokenValido/autenticado(req)/cookieSessao/cookieLogout/lerCookies/isHttps`.
- **preparos.js** — sub-receitas da casa (costela desfiada, abacaxi caramelizado, molho…). Um preparo é um ingrediente normal com `ing.receita = {itens:[{ingrediente_id,quantidade}], rendimento, unidade_rendimento, rendimento_base}`; `custo_base` é **derivado** (Σ componentes ÷ rendimento_base). API: `ehPreparo(ing)`, `custoReceita(receita)`, `montarReceita(body, base, idProprio)` (valida; **preparo não contém preparo** — 1 nível, anti-ciclo), `recalcular(ing)`, `recalcularPreparosComIngrediente(id)` (chamado em toda mudança de preço; propaga p/ fichas via `propagarPreco`), `registrarProducao(ing, levas)` ("produzi uma leva": entrada do rendimento + saída dos componentes no estoque).
- **whatsapp.js** — `processarMensagem(texto, de)` → `{reply, log}`. Interpreta PT: caixa (entrou/saiu+valor), estoque (entrada/baixa/contagem com qtd+unidade), compra (comprei item qtd valor), consultas (caixa/estoque), ajuda. Acha ingrediente por nome (`escaparRegex` antes de montar RegExp — nomes com `()`/`-` não quebram). **Entende embalagem**: "comprei milho 6 latas 30", "baixa alface 2 pés" — `EMB_PALAVRAS` genéricas + nomes de embalagem cadastrados → unidade `'emb'` (compra calcula custo via `conteudoBaseEmbalagem`; item sem embalagem cadastrada recebe aviso `embalagem_desconhecida`). Compra de **preparo é bloqueada** (`compra_preparo`); compra recalcula preparos que usam o item. Extratores com fronteira de palavra — dígito em nome ("Carne 80/20") não vira valor/quantidade.
- **auditoria.js** — `executar()` → `{resumo, problemas[]}`; `corrigir(acao)`. Varre TODO o sistema atrás de erros de LÓGICA/modelagem (não digitação). Cada problema: `{severidade:'critico'|'aviso'|'info', categoria, titulo, detalhe, alvo?, sugestao?, acao?}`. Detecta: unidade base inválida; ingrediente sem preço (crítico se usado em ficha confirmada); **embalagem incompatível/sem conteúdo** (dimensão ≠ unidade_base); **custo por unidade implausível** (>R$500/kg, >R$300/L, >R$250/un); **"un" usado em qtd alta numa ficha** (>10 → padrão "lata contada inteira"); nomes duplicados; estoque negativo; ficha com ingrediente removido; ficha no prejuízo (custo≥preço); CMV suspeito (<8% ou >60%); **CMV cache defasado** vs cálculo ao vivo; fator_correcao fora de 1–3; divergência estoque×último movimento; movimentos órfãos; mês com custos sem vendas. **Auditoria profunda também checa integridade**: id ausente/duplicado (ingrediente e ficha), custo/estoque não-numérico, lista de ingredientes corrompida, ingrediente repetido na mesma ficha, qtd≤0, preço de venda≤0, cadeia de movimentos descontínua, saldo negativo no log, datas inválidas/futuras (movimentos e caixa), caixa com tipo/valor inválido, competência inválida/duplicada e valores negativos em custos, contagens com itens fantasma, fornecedores duplicados, login sem auth_secret. **Categoria "Segurança dos dados"**: alerta CRÍTICO se na Vercel sem KV (dados voláteis); status de backup (modo local). `corrigir(acao)` só faz operações SEGURAS: `reconfirmar_fichas` (recalcula cache defasado), `sincronizar_estoque` (loga ajuste realinhando histórico ao estoque atual), `limpar_movimentos_orfaos`.
- **backup.js** — `exportar()` (pacote `{app,versao,exportado_em,modo,dados}` SEM settings), `validar(pacote)` (barra arquivo malformado), `restaurar(pacote)` (guarda estado atual antes; `importarBanco`), `info()` (modo, kv_ativo, na_vercel, contagens por coleção, backups locais).

## API (`src/api/`) — tudo sob `/api`
- **routes.js**: ingredientes (`GET`, `POST /ingredientes/pendente`, `POST /ingredientes` [compra: modo medida OU `modo:'embalagem'`; **bloqueada p/ preparo (409)**; devolve `preparos_atualizados`], `PUT/:id` [nome, unidade_base, embalagem; **não muda base de preparo**], `DELETE/:id` [bloqueado se em ficha OU em receita de preparo], **`POST /ingredientes/:id/converter-uso`** [item "un" usado pesando — alface/costela: body `{unidade:'g'|'kg'|'ml'|'L', conteudo, nome_unidade?, valor_unidade?}`; converte custo, estoque (com ajuste logado e cadeia preservada), mínimo, **fichas** (qtd×peso + recalcula confirmadas) e **receitas de preparo**; valor_unidade opcional vira compra no histórico]); **preparos** (`POST /preparos`, `PUT /preparos/:id`, `POST /preparos/preview` [custo sem salvar], `POST /preparos/:id/producao` body `{levas}`); fichas (CRUD + `/:id/confirmar`, `/rascunho`, `/cmv`); `GET /relatorio`; custos-fixos (CRUD, aceita `vendas_detalhe` por tipo); compras (`/fornecedores`, `/compras/analise`); estoque (`/estoque`, `/estoque/movimento`, `/estoque/contagem`, `/estoque/contagens`, `PUT /estoque/:id/minimo`, `/estoque/movimentos`, **`GET /estoque/consumo?data=`** [gasto do dia em R$], **histórico**: `/estoque/historico/snapshot?data=`, `/timeline?ingrediente_id=`, `/comparar?a=&b=`); caixa (`/caixa/categorias`, `GET/POST /caixa`, `DELETE /caixa/:id`); **auditoria** (`GET /auditoria`, `POST /auditoria/corrigir` body `{acao}`); **backup** (`GET /backup/info`, `GET /backup/exportar` [download com `Content-Disposition`], `POST /backup/restaurar` body = pacote). - **auth.js** (`/api/auth`): `GET /status`, `POST /setup|login|logout|senha`. Define cookie ANTES de `res.json`.
- **webhook.js** (`/api/webhook`): `GET/POST /whatsapp` (Meta Cloud API), `POST /whatsapp/test` (simulador), `GET /whatsapp/log`. Segurança: verify token, HMAC `x-hub-signature-256` (se `WHATSAPP_APP_SECRET`), lista `WHATSAPP_ALLOWED`.

## Convenções / regras de negócio (IMPORTANTES)
- **Preparo** (`ing.receita`): custo SEMPRE derivado da receita — sem compra, sem edição direta de custo (guardas na API e no WhatsApp). Preparo não contém preparo (1 nível). Recalculado em toda mudança de preço de componente (`recalcularPreparosComIngrediente`) e auditável (`recalcular_preparos`). No estoque é um item normal (produção = entrada do rendimento + baixa dos componentes).
- **Unidade de USO** do ingrediente (`unidade_base`): g/ml/un — é o que a ficha usa. **Custo** (`custo_base`) é sempre **por unidade base**, 6 casas internas, exibido 2 casas.
- **Embalagem** (`ing.embalagem = {nome, conteudo, unidade}`): ponte "1 lata = 340 g" para quem **compra por pacote e usa por grama**. Compra modo embalagem e movimentos aceitam unidade `'emb'`. Estoque é sempre guardado em unidade base; UI mostra equivalente em embalagens.
- **Moeda** R$ pt-BR (`Fmt.moeda`). **Datas diárias** (caixa/contagem/histórico) no fuso **America/Sao_Paulo**.
- **CMV%** = custo_total / preço_venda × 100. Faixa saudável Abrasel 25–33%. Rateio de custos fixos = total_mensal / produtos_vendidos_mes (opcional por ficha via `incluir_rateio`).
- Toda compra registra **entrada automática** no estoque. Todo movimento grava em `movimentos_estoque` com `estoque_antes/estoque_depois/data` → base do histórico/time-travel.

## Bugs já resolvidos (NÃO reintroduzir)
- **CMV — arredondar só no fim** (`cmv.js calcularCMV`): somar `ing.custo_base*qtd*fator` com precisão e `arredondar` o total UMA vez. Arredondar cada item antes de somar zerava temperos baratos (1g de sal virava R$0,00).
- **Mudança de unidade de uso loga ajuste** (`routes.js logarZeragemEstoque`, usado no `POST /ingredientes` quando `baseMudou` e no `PUT /ingredientes/:id`): ao zerar o estoque por troca de unidade, gravar movimento `ajuste`→0. Sem isso, o estoque atual divergia do histórico e a foto por data mentia.
- **Embalagem incompatível é limpa** no `PUT` quando a unidade de uso muda e a embalagem antiga fica com dimensão ≠ base (e não veio embalagem nova). Idem no `POST` modo medida.
- **Webhook**: gate libera SÓ `/webhook/whatsapp` exato. `/test` e `/log` exigem login (antes qualquer um injetava lançamentos). `/api` desconhecido → 404 JSON (não HTML).
- **RegExp segura** em `whatsapp.acharIngrediente` (`escaparRegex`) — nomes com `()`/`-`.
- **Extratores do WhatsApp com fronteira de palavra** (`(?<![\w/])`/`(?![\w/])`): sem isso, "baixa carne 80/20 quebra" virava lançamento de R$ 80 (o dígito do NOME era lido como valor).
- **`ficha.tipo`** validado contra `VENDAS_TIPOS` em `montarFicha` (default `hamburguer`).
- **Perda de dados**: escrita atômica (local) + anti-wipe (KV) + backups automáticos + export/import (ver "Durabilidade"). NÃO remover essas proteções.
- **Aba Auditoria é interna** — nunca colocá-la de volta na barra visível dos usuários (`#tab-btn-auditoria` deve ficar `hidden`).
- Use a **aba Auditoria** após mudanças grandes: detecta o clássico "lata contada inteira", erros de integridade e risco de perda de dados, com correção automática segura.
